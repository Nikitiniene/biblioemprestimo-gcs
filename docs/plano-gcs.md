# Plano de Gerência de Configuração de Software

## 1. Sobre o projeto

O projeto Biblioempréstimo é um sistema de gerenciamento de empréstimos de livros. A ideia é facilitar o cadastro de livros, a consulta ao catálogo, os empréstimos e as devoluções.

Neste trabalho, vamos utilizar o GitHub para organizar os arquivos do projeto e acompanhar as alterações realizadas.

## 2. Arquivos que serão controlados

Os principais arquivos que vamos controlar são:

- Documento de requisitos do sistema (ERS).
- Documentos e anotações do projeto.
- Código-fonte do sistema, quando estiver disponível.
- Arquivos de testes, quando forem criados.
- Relatório final e capturas de tela do trabalho.

## 3. Organização dos arquivos e branches

Os arquivos serão organizados em pastas para facilitar a localização.

No GitHub, utilizaremos a branch `main` para manter a versão principal do projeto. Quando for necessário fazer uma alteração, poderemos criar uma nova branch, usando nomes como `feature/cadastro-livros` ou `fix/correcao-cadastro`.

## 4. Como vamos registrar as alterações

Cada alteração importante será salva por meio de um commit. Para facilitar a identificação, utilizaremos mensagens curtas que expliquem o que foi feito.

Alguns exemplos são:

- `docs: adiciona documentação`
- `feat: cria cadastro de livros`
- `fix: corrige problema no cadastro`

## 5. Controle de versões

O histórico do GitHub permitirá acompanhar as mudanças e consultar versões anteriores dos arquivos.

Também poderemos utilizar tags, como `v1.0.0`, para identificar uma versão considerada estável do projeto.

## 6. Trabalho em equipe e revisão

O ideal é que cada integrante trabalhe em uma branch separada. Depois, as alterações poderão ser revisadas e incorporadas à branch principal por meio de um merge.

Como parte da atividade, também será feita uma simulação de conflito entre alterações, para demonstrar como esse problema pode ser identificado e resolvido.

## 7. Backup e recuperação

O GitHub será utilizado para manter uma cópia remota dos arquivos e o histórico das alterações. Caso seja necessário recuperar uma versão anterior, poderemos consultar os commits e restaurar os arquivos correspondentes.

## 8. Responsabilidades

Cada integrante deverá contribuir de acordo com a função combinada pelo grupo, ajudando a manter os arquivos organizados e as alterações registradas.

As contribuições serão identificadas pelo histórico do GitHub, permitindo verificar o que foi realmente realizado durante o trabalho.
